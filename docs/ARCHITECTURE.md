# Kynex architecture

Plain-language version: the "Architecture & security" tab of the Kynex Google Sheet.

## The four pieces

```
 Phone / laptop browser (installable web app)
 ┌──────────────────────────────────────────┐
 │ artifacts/web      screens only          │
 │ lib/motion         camera engine         │  video never leaves the device
 └──────────────┬───────────────────────────┘
                │ https, JSON, contract = lib/api-spec/openapi.yaml
 ┌──────────────▼───────────────────────────┐
 │ artifacts/api-server                     │  every rule and permission check
 └──────────────┬───────────────────────────┘
                │ lib/db (Drizzle ORM)
 ┌──────────────▼───────────────────────────┐
 │ PostgreSQL (Replit now; India region      │
 │ before real patients)                     │
 └──────────────────────────────────────────┘
```

| Folder | What it is | Rules |
|---|---|---|
| `lib/motion` | Camera engine: landmarks to angles, reps, form checks for 25 exercises. | No screens, network or database. Pure functions, unit-tested. |
| `lib/api-spec` | `openapi.yaml`, the contract between apps and server. | Change the contract first, then `pnpm codegen`. |
| `lib/api-client-react` | Generated React Query hooks for screens. | Never edit `src/generated` by hand. |
| `lib/api-zod` | Generated validators the server uses on input and output. | Never edit `src/generated` by hand. |
| `lib/db` | Database connection and table definitions. | See "Database rules" below. |
| `artifacts/api-server` | Express server. Only thing that touches the database. Serves the web app on the same address. | Every route validates input and checks permissions. |
| `artifacts/web` | Vite + React screens, installable on phones (PWA). | No business rules. Wrapped into store apps later with Capacitor. |

## Database rules

- `id` is a random UUID primary key.
- Every row that belongs to a clinic has `clinic_id`.
- `created_at`, `updated_at`, and `created_by` where a person made the row.
- Status-like fields are text validated by the API, not Postgres enums.
- Derived values (adherence, alerts) are computed when read, not stored.
- Migrations are SQL files generated by `pnpm --filter @kynex/db generate`, logged in `docs/DATABASE_SCHEMA.md`, and run by hand on Replit after review.

## Security baseline

- Video is analysed on the device; only numbers reach the server.
- Strict security headers in production (CSP, HSTS, no framing, camera only for our own pages).
- API rate limit (300 requests a minute per address), 100 kB request body limit.
- Errors never send internal details to the browser.
- Secrets only in Replit Secrets / environment variables, never in the repository.
- GitHub Checks (type checks, tests, build, dependency audit) must pass before merging; Dependabot proposes security updates.
- Sign-in (M1): passwords hashed with scrypt (built into Node, no extra package); sign-in held in an
  `HttpOnly`, `Secure`, `SameSite=Lax` cookie (`__Host-` prefix in production) whose token is stored only as a
  SHA-256 hash; 5 wrong passwords lock an account for 15 minutes, plus 20 sign-in attempts per 15 minutes per address;
  changes (POST) coming from other websites are refused.
- Every API route checks the signed-in role on the server and only reads its own clinic's rows; automated tests
  prove patients and clinicians can't open admin routes.

## Avoiding lock-in

Only standard Node, Postgres and environment variables are used. Nothing depends on Replit-only services, so the app can move to another host or an India-region database by changing `DATABASE_URL` and the deploy commands.
